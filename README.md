# Тестовое задание Django

В проекте реализован веб-сервис на Django для работы с организациями и магазинами.

## Быстрый запуск

### 1. Установка зависимостей

Зависимости проекта описаны в `pyproject.toml` и `poetry.lock`.

При установленном Poetry:

```bash
poetry install
```

### 2. Проверка проекта

```bash
python manage.py check
```

Ожидаемый результат:

```text
System check identified no issues (0 silenced).
```

### 3. Запуск сервера

```bash
daphne config.asgi:application -p 8000
```

После запуска доступны:

- Admin: `http://127.0.0.1:8000/admin/`
- Swagger: `http://127.0.0.1:8000/api/swagger/`

Для обработки фоновых задач необходимо запустить в отдельном терминале:

```bash
python manage.py process_tasks
```

## Что реализовано

### 1. Organization и Shop

Созданы две модели:

- `Organization` — название и описание организации.
- `Shop` — организация, название, описание, адрес, индекс и признак удаления.

Одна организация может иметь несколько магазинов.

### 2. API

Реализованы следующие методы:

- `GET /api/organizations/` — получает список организаций и связанных с ними магазинов. Магазины с `is_deleted=True` не возвращаются.
- `PUT /api/shops/{id}/` — обновляет данные магазина.
- `GET /api/organizations/{id}/shops_file/` — скачивает CSV-файл с магазинами организации.

### 3. JWT авторизация

API защищено JWT-авторизацией.

Для получения токена:

`POST /api/token/`

Для обновления токена:

`POST /api/token/refresh/`

### 4. Swagger

API можно посмотреть и протестировать через Swagger:

`http://127.0.0.1:8000/api/swagger/`

### 5. Фоновая задача и email

После изменения магазина через PUT создаётся фоновая задача с помощью `django-background-tasks`.

Задача отправляет email.

Для тестирования письмо выводится прямо в консоль.

Для обработки фоновых задач используется:

```bash
python manage.py process_tasks
```

### 6. WebSocket

Для WebSocket используется Django Channels.

Адрес подключения:

`ws://127.0.0.1:8000/ws/shops/`

После изменения магазина через PUT клиент получает данные изменённого магазина через WebSocket.

Для запуска используется Daphne:

```bash
daphne config.asgi:application -p 8000
```

### 7. Логирование

Добавлено логирование API-методов.

Например:

```text
API method: GET
API method: PUT
```

Также сами API-методы записывают дополнительные сообщения в лог.

### 8. Django Admin

В административной панели добавлена модель `Organization`.

Магазины отображаются внутри организации через `ShopInline`, поэтому их можно добавлять и редактировать прямо на странице организации.

Также был переопределён шаблон Django Admin, подключены свои CSS и JavaScript.

JavaScript выводит сообщение в консоль:

```text
Custom Django Admin JavaScript подключен!
```

### 9. Данные для входа в Django Admin

Административная панель:

`http://127.0.0.1:8000/admin/`

Тестовый пользователь:

- Логин: `Katya`
- Пароль: `0000`

Это тестовые данные, созданные специально для проверки проекта.

После входа можно открыть `Organizations` и посмотреть тестовую организацию и связанные с ней магазины.
